# Contributing

Thanks for helping improve the handbook.

## Guidelines

- Prefer current standards and official provider documentation.
- Never commit real credentials, tokens, private keys, or personal data.
- Add negative/security tests when changing authentication logic.
- Explain security-sensitive behavior.
- Keep provider-specific assumptions isolated.

## Suggested structure

```text
Purpose
Architecture
Implementation
Failure modes
Security considerations
Testing
References
```

## Security reports

Do not post real secrets or sensitive vulnerabilities in public issues. Use the repository's private security-reporting process when available.
